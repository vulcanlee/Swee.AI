第一幕 · 舊世界

問題不在你的同事不夠認真。
問題在 PDF 這個格式本身。

缺陷一

它是「印出來的樣子」，
不是「內容」

PDF 記錄的是每個字要印在紙上的哪個座標。掃描件更徹底——那根本就是一張圖片，連搜尋都搜不到。

缺陷二

它沒有結構

你沒辦法叫電腦「把所有罰則條款列給我」。因為 PDF 裡沒有「罰則」這個欄位，只有一堆座標上的文字。

缺陷三

它沒辦法比對

兩份 80 頁的合約攤在桌上，人眼比對幾乎不可能做到不漏。而你需要的正是「不漏」。

講者備忘 這一頁的作用是把責任從「人」轉移到「格式」。企業管理者聽到「你的同事不夠認真」會防衛， 聽到「這是格式的問題」會點頭。三個缺陷念一遍就好，不要展開——真正的痛在後面三頁。

我們憑什麼敢這樣講

三條工程紀律。

紀律一

頁碼是「算」出來的，
不是 AI 說的

我們只要求模型在每頁內容前輸出一個中性分界符，頁碼由程式依批次起始頁換算。分界符數量對不上該批次頁數，就退回較粗的頁段標記。

錯的頁碼比沒有頁碼更糟，對不上就不猜。
紀律二

數字不交給 AI 算

各條款類型、各風險等級、各覆核狀態的數量，一律由程式即時計算，不經過模型。

模型算錯的數字，看起來一樣可信。
紀律三

每一次呼叫都記帳，
失敗也記

因為失敗照樣計費。而且回應碼是 200 不代表成功——我們判定的是回應內容裡的狀態欄位，不是 HTTP 狀態碼。

看不到的成本，就是控不住的成本。
講者備忘 這一頁是我們相對於通用 AI 真正拿得出手的差異，而且它不是功能，是紀律——功能可以抄，紀律不好抄。 面對技術背景的聽眾可以展開講紀律一的細節；面對純管理階層，三句引言念完就夠了。 引言是產品文件裡的原句，不是行銷詞。

貫穿全系統的一條原則

寧可不給，
也不給錯的。

所以我們的用量統計只給你 token 數與呼叫次數，不給新台幣金額。

因為每個模型費率不同、而且還會調價。換算錯的金額，比沒有金額更糟。
這跟頁碼是同一條原則。

講者備忘 這一頁看起來是在講缺點，其實是在證明紀律是真的。 任何人都可以說「我們很嚴謹」，但只有真的嚴謹的產品，才會為了原則放棄一個客戶想要的功能。 如果客戶追問「那我怎麼知道花了多少錢」，回答：「我們給你 token 數與模型名稱， 你乘上你自己的合約費率——那個數字才是對的。」

企業關切 · 安全與權限

機密文件，
不該人人可見。

列級權控

每份文件貼「團隊」標籤

沒有貼標籤的才是公開。使用者看得到什麼，由他所屬的團隊決定——不是由他能不能進入那一頁決定。

動作級權限

不只是「能不能進這一頁」

檢視、新增、修改、刪除、匯出，每個動作各自授權。看得到不等於改得動，改得動不等於匯得出去。

人在迴路

每一條都留著覆核狀態

條款有覆核狀態，題目有審題狀態。系統預期你要看過——這是設計，不是待改進事項。

網頁介面與 API 共用同一套權限判定，不會有一邊擋住、另一邊放行的情況。

講者備忘 如果對面有 IT 或資安人員，這一頁要慢慢講，並且主動提「網頁與 API 共用同一套判定」—— 這是他們最常踩到的坑，聽到你主動提會加很多分。 也可以在這裡回收第 9 頁的第四個問題：「還記得剛剛說貼上去就是貼上去了嗎？這就是差別。」

誠實邊界

我們刻意不做的四件事。

不做全自動

AI 產出的是初稿。條款可能抽漏、風險等級可能判得太保守或太寬鬆。所有結果都設計成可覆核，就是因為預期你要看過。

不做萬用轉檔

目前只收 PDF，而且不支援加密的 PDF。Word、Excel、簡報請先自行另存成 PDF。（教材另可收 Markdown。）

不做 DMS

不做版本樹、不做簽核流程、不做全文檢索引擎。那些系統你已經有了，我們不打算再做一套。

不做即時

解析是背景工作，一份 80 頁的 PDF 要跑好幾分鐘。而且全站同時只有一個工作者，多人上傳會排隊——所以我們讓你看得到自己排第幾個。
